# Sijilak (سجلك)

B2B sales and ZATCA e-invoicing mobile app for the Saudi market, built by Digital Harbor.
Flutter, Arabic (RTL) first with English as a second locale. Pipeline/leads, customers,
quotes, invoices, notifications and search.

The backend is not delivered yet, so the app currently runs against an **in-app mock backend**
(JSON in `assets/mock/`). The switch to real HTTP is isolated behind one interface (see below).

## Architecture

```
lib/
  main.dart              entry point
  app/                   app shell, router host, DI composition root (app/di/injection.dart)
  core/                  cross-cutting: theme, routing (go_router), network (ApiClient + mock),
                         error, l10n helpers, layout/responsive, constants (app_config.dart)
  features/<feature>/    one folder per feature (auth, home, pipeline, customer, quote,
                         invoices, notifications, search, account); `_template/` is the skeleton
    data/                datasources (remote + mock API), models, repository implementations
    domain/              entities, repository interfaces, use cases (pure Dart)
    presentation/        cubits (flutter_bloc), screens, widgets, constants
    di/                  <feature>_module.dart, registers the feature into get_it
  shared/                widgets shared between features
  l10n/                  ARB files + generated localisations (lib/l10n/gen)
```

- Layering: presentation (cubit) -> domain (use case, repository interface) -> data (repository impl -> data source).
- State management: `flutter_bloc` cubits. DI: `get_it`, composed in `lib/app/di/injection.dart`.
- Mock backend to real HTTP: data sources talk to the `ApiClient` abstraction
  (`lib/core/network/api_client.dart`). Today `MockApiClient` is registered; with
  `USE_MOCK_BACKEND=false` the HTTP client is used instead, pointing at `API_BASE_URL`.

## Run (development, mock backend)

```
flutter pub get
flutter run --dart-define-from-file=env/dev.json
```

Environment keys (compile-time, passed with `--dart-define-from-file`):

| Key                | Meaning                                         | dev  | staging | prod |
|--------------------|-------------------------------------------------|------|---------|------|
| `API_BASE_URL`     | Base URL of the backend API                     | `https://api.dev.sijilak.example` | `https://api.staging.sijilak.example` | `https://api.sijilak.example` |
| `USE_MOCK_BACKEND` | `true` = in-app mock, `false` = real HTTP       | true | false   | false |
| `APP_LOCALE`       | Default locale (`ar` or `en`)                   | ar   | ar      | ar   |

The URLs in `env/*.json` are placeholders; replace them once the backend team publishes real ones.
Never put secrets in these files (they are committed). Use `env/*.secret.json` (gitignored) for anything private.
Android debug builds may call `http://10.0.2.2` / `localhost` (cleartext allowed only in
`android/app/src/debug/res/xml/network_security_config.xml`); release builds are HTTPS only.

## Localisation

Strings live in `lib/l10n/app_ar.arb` (template) and `app_en.arb`. New strings are authored as
`l10n_additions/<topic>.json` (`{"ar": {...}, "en": {...}}`) and merged with:

```
python tool/merge_arb.py
```

which merges idempotently and runs `flutter gen-l10n`. `lib/l10n/gen/` is **committed** to git:
it is regenerated by `flutter pub get`/`gen-l10n`, but keeping it tracked makes fresh
clones and CI analyze work without a generation step and keeps diffs reviewable.
Native display name and Face ID text are localised in `android/app/src/main/res/values*/strings.xml`
and `ios/Runner/{ar,en}.lproj/InfoPlist.strings`.

## Release build (Android)

1. Create the upload keystore once (keep it and its passwords backed up, never commit it):
   ```
   keytool -genkey -v -keystore upload-keystore.jks -storetype JKS -keyalg RSA -keysize 2048 -validity 10000 -alias upload
   ```
2. Copy `android/key.properties.example` to `android/key.properties` and fill it in (gitignored).
   Without `key.properties`, release builds fall back to the debug key (fine locally, not for stores).
3. Bump the version in `pubspec.yaml`: `version: 1.0.0+1` -> `name+buildNumber`
   (`versionName` = 1.0.0, `versionCode` = 1; the build number must increase on every Play upload).
   One-off override: `--build-name=1.2.0 --build-number=12`.
4. Build:
   ```
   flutter build appbundle --release --dart-define-from-file=env/prod.json
   flutter build apk --release --dart-define-from-file=env/prod.json
   ```
   Release uses R8 minification and resource shrinking (`android/app/proguard-rules.pro`).
   Keep `build/app/outputs/mapping/release/mapping.txt` to de-obfuscate crash traces.

CI (`.github/workflows/ci.yml`) runs analyze, test and a release build. For a signed CI build set the
secrets `ANDROID_KEYSTORE_BASE64` (`base64 -w0 upload-keystore.jks`), `ANDROID_KEYSTORE_PASSWORD`,
`KEY_ALIAS`, `KEY_PASSWORD`.

iOS: open `ios/Runner.xcworkspace` on a Mac, set the signing team, then
`flutter build ipa --release --dart-define-from-file=env/prod.json`.

## Release checklist

- [ ] Confirm the application id / bundle id with the company.
- [ ] Real API URLs in `env/staging.json` and `env/prod.json`; `USE_MOCK_BACKEND=false`.
- [ ] Version bump in `pubspec.yaml`.
- [ ] Release keystore created and backed up; Play App Signing enabled.
- [ ] Google Play Console and Apple Developer accounts, store listing (ar + en), screenshots, age rating.
- [ ] Privacy policy URL and data-safety / App Privacy answers.
- [ ] TODO ZATCA: e-invoicing compliance (Phase 2 integration, CSID onboarding, QR, XML/UBL, hash chain) to be confirmed with the backend team.
- [ ] Test on real devices (Arabic RTL, English, biometrics, small and large screens).

## Fonts

Tajawal (OFL 1.1). The font files in `assets/fonts/` are modified copies. The OFL requires that modified
versions do not use the Reserved Font Name: rename the family/files before distributing and include
the OFL licence text with the app.
